# RV64 处理器目标架构

> 本文是项目的架构契约与演进边界，不是对当前 RTL 完成度的声明。未在仓库中通过验证的功能只能标记为“计划”或“接口预留”。

## 1. 范围与术语

本项目面向一个基于 SystemVerilog 的 64 位 RISC-V 单核处理器，目标是从 `RV64I` 起步，逐步扩展为可运行 OpenSBI、Linux 和 Ubuntu 用户空间的 `RV64GC`/特权虚拟内存系统。处理器采用顺序发射、顺序提交的基本五级流水线，核心使用独立取指和数据通道的现代改进哈佛结构。软件看到的地址空间可以统一映射 RAM 与 MMIO，但这不意味着核心使用统一的取指/数据端口；I/D cache、通道和下层互连保持物理分离。

本文中“必须”表示架构契约；“应”表示默认设计选择；“可以”表示实现者可在不破坏接口与验证属性的前提下选择的方案。

### 1.1 目标基线

| 项目 | 基线决定 |
| --- | --- |
| 数据宽度 | `XLEN=64`，通用寄存器和地址均为 64 位 |
| ISA 与对齐 | 从 `RV64I/IALIGN=32` 起步；当前 `RV64IMAC/IALIGN=16`，小端（little-endian） |
| 流水线 | `IF/ID/EX/MEM/WB` 五级，单发射、顺序提交 |
| 存储模型 | 改进哈佛：独立 32 位取指端口和 64 位数据端口；下层内存控制器可汇聚至 DRAM |
| 重置 | 同步或异步实现由顶层决定，但复位释放后 PC 和提交状态必须确定 |
| 异常 | 初期保证同步异常可观察且不产生错误的后续提交；完整陷阱返回依赖特权阶段 |
| 验证 | Verilator 为主要回归和波形工具；Icarus 仅用于快速冒烟回归 |

### 1.2 当前状态边界

架构文档不假定已有 RTL、仿真脚本或平台设备。每个路线图阶段的“验收门”只有在相应测试、波形或软件启动证据存在时才可标记完成。不得以模块名、注释或未运行的代码替代运行时证据。

截至 2026-08-08，仓库当前实现已形成 `RV64IMAC` 功能基线：RV64I/RV64M 已有定向回归，RV64A 已接入单核阻塞式 D-port，RV64C 整数压缩形式已接入对齐取指与五级流水。A 扩展目前只保证核心内部、顺序单发射且每通道单 outstanding 模型下的语义；外部总线原子属性、随机并发、访问错误和编译器自旋锁验收尚未完成，因此路线图阶段 2 仍未关闭。多核一致性和 DMA reservation 监听属于后续 cache/互连阶段。F/D、Zicsr/Zifencei、特权架构和 MMU 仍是后续阶段。

## 2. 顶层组织

初期顶层由处理器核、独立的取指/数据端口和仿真平台组成；后续由 I-cache、D-cache 和 MMU 接入互连，主存请求再汇聚到统一 DRAM 控制器。RAM/ROM 属于主存层，硬盘或块设备属于独立设备层，由 MMIO 控制器和 DMA 主设备接入，不能把设备存储与主存混称：

```text
                 +----------------------+
                 |      rv64_core       |
                 | IF ID EX MEM WB      |
                 |  |             |     |
                 | I-port       D-port  |
                 +--+-------------+-----+
                    |             |
                  I-MMU         D-MMU
                    |             |
                 I-cache       D-cache
                    |             |
                    +----互连----------------+
                    |                        |
          unified DRAM controller       MMIO fabric
                    |                        |
                 DRAM/RAM             block controller
                                             |       |
                                        disk image   +-- DMA master --回到互连
```

改进哈佛只约束核心侧端口和缓存通道分离；更高层互连可以将 I/D 主存请求汇聚到统一的 DRAM 控制器。DRAM 控制器必须保留请求来源、访问类型、权限和响应错误；设备地址则由互连路由到独立 MMIO fabric。MMIO 设备事务不得被 D-cache 当作普通 RAM 缓存，块设备的数据介质也不属于主存地址空间。

### 2.1 时钟、复位与提交

* 顶层提供单一 `clk`；时钟域跨越不是初期核心的一部分。
* 复位时禁止产生有效内存请求和提交事件，流水寄存器置为无效气泡。
* 复位释放后的第一个取指地址由平台参数 `RESET_PC` 提供，并按指令对齐。
* 核心应导出可选的提交观测接口（PC、指令、写回寄存器、内存副作用、异常），供差分测试和形式断言使用。该接口不是软件可见 ISA。

## 3. RV64I 基线

### 3.1 寄存器与编码

* `x0` 始终读取为零，任何写入都被丢弃；`x1` 默认作为链接寄存器。
* `x2` 仅具有 ABI 约定的栈指针含义，硬件不作特殊处理。
* 所有立即数按 RV64I 规定扩展到 64 位；`W` 类指令先在低 32 位运算，再进行符号扩展。
* 未实现或保留编码产生非法指令异常，不能静默当作普通算术指令。

### 3.2 初始指令集合

第一阶段应覆盖 RV64I 基础整数指令：

* 上层立即数和地址：`LUI`、`AUIPC`。
* 控制流：`JAL`、`JALR`、六种条件分支。
* 整数运算：寄存器/立即数版本的加减、逻辑、比较、移位，以及 `ADDW/SUBW/SLLW/SRLW/SRAW` 及其立即数形式。
* 访存：`LB/LH/LW/LD/LBU/LHU/LWU`、`SB/SH/SW/SD`。
* 顺序与环境：RV64I 的 `FENCE`、`ECALL`、`EBREAK` 解码和异常边界。

`FENCE.I` 属于 `Zifencei`，CSR 指令属于 `Zicsr`，两者不是当前规范拆分下的 RV64I 基础编码。项目会在特权/软件兼容阶段完成它们；早期若尚未启用，应产生可诊断的非法/未实现陷阱。标准 `G` 配置还要求 `Zicsr` 和 `Zifencei`，因此只完成 I/M/A/F/D/C 不能宣称完整 RV64GC。

原子、浮点、压缩指令不属于 RV64I 门的通过条件，分别见路线图。

### 3.3 RV64M 扩展

当前实现覆盖 `MUL/MULH/MULHSU/MULHU`、`DIV/DIVU/REM/REMU` 以及 `MULW/DIVW/DIVUW/REMW/REMUW`。除零和最小负数除以 `-1` 按规范返回确定结果，所有 W 类结果符号扩展到 64 位。

乘除单元使用 `start/busy/done` 握手，EX 级在结果完成前保持 M 指令和年轻流水项，允许更老的 MEM/WB 工作继续提交。当前数据运算函数使用 SystemVerilog 乘除运算符形成固定延迟的功能基线；在频率、面积和综合目标确定后，替换为迭代或流水乘除实现，外部握手和提交语义保持不变。

### 3.4 RV64A 功能基线

当前实现覆盖 `LR.W/LR.D`、`SC.W/SC.D`，以及 `AMOSWAP/AMOADD/AMOXOR/AMOAND/AMOOR/AMOMIN/AMOMAX/AMOMINU/AMOMAXU` 的 W/D 两种形式。`LR.W` 与所有 AMO.W 将读到的旧 32 位值符号扩展到 64 位后写回；SC 成功返回 `0`，reservation 不匹配时返回非零且不发出数据写事务。

reservation 是核心内部的单核状态。普通 store 会清除 reservation，SC 会消费 reservation；AMO 在阻塞式 D-port 上依次完成读和写，并在完成前阻塞当前数据通道。该结构可以防止本核心的另一个访存插入 AMO 读写之间，但没有向外部互连提供锁定、独占或原子事务属性，因而不能阻止其他总线主设备介入。

指令中的 `aq/rl` 位在当前顺序单发射、单 outstanding、无投机访存模型下不需要增加额外硬件重排屏障：所有核心侧内存事务已经按强顺序完成。此结论只适用于当前模型；引入 store buffer、cache miss 并发、多 outstanding 或乱序执行时，必须重新实现并验证 acquire/release 约束。

当前 A 基线不包含外部总线原子锁定、多核 cache 一致性、其他 hart 写入导致的 reservation 失效、DMA 写监听、随机外部主设备并发或 D-port 访问错误。以上边界不得由“RV64IMAC 功能基线”推导为系统级原子支持。

### 3.5 RV64C 功能基线

当前解压器覆盖 RV64C 的整数形式：`C.ADDI4SPN/C.LW/C.LD/C.SW/C.SD`，`C.ADDI/C.NOP/C.ADDIW/C.LI/C.LUI/C.ADDI16SP`，压缩移位、逻辑、W 类运算、跳转与条件分支，以及 `C.SLLI/C.LWSP/C.LDSP/C.JR/C.MV/C.EBREAK/C.JALR/C.ADD/C.SWSP/C.SDSP`。标准 HINT 合法并解压为规范 NOP；保留编码和未启用 Zc 子扩展保持非法。依赖 D 扩展的 `C.FLD/C.FSD/C.FLDSP/C.FSDSP` 在 F/D 接入前保持非法。

核心以 4 字节对齐地址访问外部 32 位 I-port。PC 位于取指字低半字时，可直接选择 16 位指令或整个 32 位字；PC 位于高半字且遇到 32 位指令时，保存当前高半字，再请求下一个对齐取指字并拼接其低半字。跨字拼接期间 PC 和流水入口保持一致，不把半条指令交给解码器。

IF/ID 与 ID/EX 携带 2/4 字节指令长度。顺序 PC、`JAL/JALR` 链接地址和异常原始指令值均使用该元数据；启用 C 后 `IALIGN=16`，控制流目标只要求 `PC[0]=0`。压缩指令在进入原有 RV64I 解码器前展开为等价 32 位指令，因此后端数据通路、冒险和异常提交规则不另建旁路。

### 3.6 地址与字节序

* 地址为字节地址，算术溢出按 64 位模运算。
* 内存采用小端序：最低有效字节位于最低地址。
* 当前启用 C 后 `IALIGN=16`，指令地址必须 `PC[0]=0`；外部 I-port 请求仍保持 4 字节对齐。未对齐指令目标和未对齐数据访问必须产生异常，而不是由内存模型“碰巧支持”。
* 实现不得把地址高位截断后再报告成功；地址位宽扩展由未来 MMU/平台阶段定义。

## 4. 五级流水线

### 4.1 流水级职责

| 级 | 主要职责 | 允许的架构状态变化 |
| --- | --- | --- |
| IF | 产生取指地址、接收指令字、计算顺序 PC | 无 |
| ID | 指令解码、寄存器堆读取、立即数生成、基本冒险检测 | 无 |
| EX | ALU、比较、分支/跳转目标、有效地址、CSR/乘法等扩展运算 | 无 |
| MEM | 通过独立数据端口完成加载/存储，检查响应错误 | 仅在事务成功后产生存储副作用 |
| WB | 选择结果并写入 `x1..x31`，产生提交事件 | 通用寄存器写回 |

所有流水寄存器带 `valid` 位。无效项是气泡，气泡不得触发内存请求、寄存器写回或提交事件。

### 4.2 PC 与控制流

* 无重定向时，`next_pc = pc + instruction_length`，其中指令长度为 2 或 4 字节。
* `JAL/JALR` 和条件分支在 EX 级决定，目标地址以 64 位加法计算；`JALR` 清除目标地址最低位。
* 分支预测不是初期特性。默认按顺序取指，分支成立或跳转确认后冲刷尚未进入 EX 的年轻指令。
* 发生重定向时，旧路径的取指请求带有 epoch/代号；响应到达后若代号过期，必须丢弃，不得写入 IF/ID。

### 4.3 流水控制优先级

同一周期多个控制条件同时成立时，按以下顺序处理：

1. 复位；
2. 已确认的同步异常或更老的内存错误；
3. 更老 MEM/LSU 项等待响应；
4. 已确认的 EX 分支/跳转重定向；
5. load-use 气泡；
6. IF 等待独立取指端口响应或背压；
7. 正常推进。

“停顿”保持产生原因所在级及其更年轻级的相关内容不变，允许不受影响的更老项提交；“冲刷”只使触发项之后的年轻级无效。老的 LSU 等待必须压住年轻的 EX 重定向，重定向可以先锁存并在 LSU 完成后生效；仅等待取指不会阻止已经到达 EX 的重定向，旧取指响应由 epoch 机制丢弃。由于 I/D 端口独立，取指背压本身不是核心结构冒险。不得用全流水清空代替精确的异常或重定向处理。

## 5. 改进哈佛核心接口

核心提供独立 instruction 和 data 事务通道。两条通道使用相同的 `valid/ready` 解耦规则，但数据宽度和语义不同：instruction 端口只进行 32 位取指，data 端口进行最大 64 位的加载/存储。核心不包含把两条通道合并为一个端口的仲裁器。

当前阶段的 `rtl/rv64_core.sv` 使用一个便于 Icarus 冒烟验证的阻塞式投影：`i_valid_o/i_ready_i/i_rdata_i` 和 `d_valid_o/d_ready_i/d_rdata_i` 在握手同周期返回数据，且每条通道至多一个未完成请求。下方的独立请求/响应信号是平台适配层和 Verilator 主回归的目标契约；把阻塞式投影替换为可多周期响应的适配器不改变流水线、异常和提交语义。任何依赖多周期响应的测试必须通过适配器验证，不能把当前零等待测试误称为已经完成背压覆盖。

### 5.1 通用握手规则

请求握手条件为 `req_valid && req_ready`，响应握手条件为 `rsp_valid && rsp_ready`。发送方不得依赖对端 `ready` 才产生 `valid`，也不得在 `valid=1 && ready=0` 时改变请求字段。接收方可以在接受请求的同周期返回响应；两条通道也可以在同一周期各自接受请求或返回响应。

初期每条通道各允许一个未完成事务，即 I-port 和 D-port 最多同时存在两个事务。未来可以用事务 ID 扩展多 outstanding，但必须保持单个通道内的响应归属和精确异常语义。

### 5.2 32 位 instruction fetch 端口

下表为逻辑信号名，具体模块可以使用一致的前缀映射：

| 信号 | 方向（核心视角） | 宽度 | 语义 |
| --- | --- | --- | --- |
| `if_req_valid` | 输出 | 1 | 取指地址有效；握手前保持 |
| `if_req_ready` | 输入 | 1 | I 侧本周期可以接受请求 |
| `if_req_addr` | 输出 | 64 | 包含当前 PC 半字的 32 位取指字地址；当前始终 4 字节对齐 |
| `if_rsp_valid` | 输入 | 1 | 取指响应有效 |
| `if_rsp_ready` | 输出 | 1 | IF 单元可以接收响应 |
| `if_rsp_data` | 输入 | 32 | 小端排列的 32 位指令字 |
| `if_rsp_err` | 输入 | 1 | 取指访问错误；转换为精确指令访问异常 |

I-port 只读，不承载普通 load/store 或 MMIO 设备访问。分支重定向后，已接受的旧路径请求用 epoch/代号作废；响应仍要握手消费，但不得进入 IF/ID。加入 C 扩展后，取指单元仍可使用 32 位端口，通过半字选择和必要的第二次取指拼接跨边界的 32 位指令。

### 5.3 64 位 data load/store 端口

| 信号 | 方向（核心视角） | 宽度 | 语义 |
| --- | --- | --- | --- |
| `data_req_valid` | 输出 | 1 | 当前加载/存储请求有效；握手前保持 |
| `data_req_ready` | 输入 | 1 | D 侧本周期可以接受请求 |
| `data_req_addr` | 输出 | 64 | 字节地址，读写都有效 |
| `data_req_write` | 输出 | 1 | `1` 为写，`0` 为读 |
| `data_req_wdata` | 输出 | 64 | 写数据，按地址低三位放置到对应字节 lane |
| `data_req_wstrb` | 输出 | 8 | 每一位对应一个字节写使能；读请求为 `0` |
| `data_req_size` | 输出 | 3 | `0/1/2/3` 分别表示 8/16/32/64 位访问 |
| `data_rsp_valid` | 输入 | 1 | 数据响应有效；响应内容在握手前保持 |
| `data_rsp_ready` | 输出 | 1 | MEM 级可以接收响应 |
| `data_rsp_rdata` | 输入 | 64 | 加载数据；存储响应可忽略该字段 |
| `data_rsp_err` | 输入 | 1 | 总线、权限或设备错误；`1` 时不得写回/提交 |

对写事务，`data_rsp_err=1` 必须表示该写没有产生外部可见副作用；不能提供该保证的总线或 MMIO 设备适配器要在写入前完成权限/地址检查。普通 RAM、MMIO 控制寄存器和 uncached 数据都经 D-port 发起，但由下层地址属性选择 D-cache、旁路或设备通路。

### 5.4 独立事务状态

IF 和 LSU 分别维护自己的 `IDLE -> WAIT_RSP -> IDLE` 状态：

* 任一通道请求握手后锁存地址、访问属性和对应流水元数据，直到本通道响应握手。
* I-port 等待不会阻止 D-port 发出请求；D-port 等待也不取消合法的取指。下层 DRAM 端口争用通过各自 `ready` 背压解决。
* I-port 的过期响应消费后丢弃；D-port 响应错误转换为对应 MEM 项的精确异常。
* 写请求必须获得成功响应后才能让流水项离开 MEM，避免错误存储被宣称提交。
* 两个通道都不得因为另一个通道的 `ready` 或状态改变自身已呈现的请求字段。

### 5.5 访问与对齐

| 操作 | `size` | 对齐要求 | 加载结果 |
| --- | ---: | --- | --- |
| byte | 0 | 无 | 按 `LB/LBU` 符号/零扩展 |
| half | 1 | 地址最低位为 0 | 按 `LH/LHU` 扩展 |
| word | 2 | 地址低两位为 0 | `LW` 符号扩展，`LWU` 零扩展 |
| double | 3 | 地址低三位为 0 | `LD` 原样 64 位 |

未对齐访问在发出请求前生成异常。实现不得拆分为多个请求，除非未来明确增加“非原子拆分访存”接口和相应异常规则。`wstrb` 必须只覆盖访问宽度对应的字节；写数据在核心端按小端 lane 对齐。

### 5.6 FENCE 与取指一致性

初期无缓存时，`FENCE` 可以作为 D-port 排空和排序屏障：在其之前的数据事务完成前，不得让之后的数据访问越过。`FENCE.I` 必须先保证较早的 D-port 写入对 instruction 通道可见，再取消旧取指、清除取指缓冲并重新取指；引入 I-cache 后还要执行规定的 I-cache 失效/同步。若实现暂不支持完整语义，必须报告可观察的非法/未实现异常，不能静默忽略。

## 6. 冒险、前递与冲刷

### 6.1 数据冒险

* 只考虑 RAW；顺序单发射使 WAR/WAW 在架构上不存在。
* EX 操作数前递优先级：`EX/MEM`（结果有效且不是加载等待）高于 `MEM/WB`，再高于寄存器堆读值。
* `x0` 永不前递为非零值。
* `JAL/JALR` 的链接值、算术结果和有效地址均可前递。
* 加载数据在响应握手后才有效。紧随加载使用结果的指令至少插入一个气泡；如果内存响应更慢，继续保持停顿。
* 分支比较和 `JALR` 基址也必须使用同一前递网络，不能只修复 ALU 普通运算。
* 存储数据在 MEM 级发起写请求前应用前递，覆盖“计算后立即存储”和“加载后存储”等序列。

### 6.2 结构冒险

核心的 I-port 与 D-port 可以同周期握手，因此 IF 与 LSU 之间没有核心侧端口结构冒险。下层统一 DRAM 控制器只有一个 DRAM 通道时，可以独立背压 I-cache 或 D-cache；公平仲裁和 QoS 属于互连/控制器职责，不能在核心中硬编码“数据永久优先”。寄存器堆至少提供两个读端口和一个写端口；若采用单端口实现，必须在流水控制中显式增加停顿并在验收门中记录。

### 6.3 控制冒险

EX 确认的跳转/分支会使 IF/ID 和当周期尚未进入 EX 的错误路径项无效。重定向 PC 只在确认目标对齐、没有更老异常的情况下生效。异常优先于年轻分支，避免错误路径改变可见状态。

## 7. 异常与精确状态边界

### 7.1 初始同步异常

至少定义以下内部异常原因和 `tval` 候选值：非法指令（指令字）、指令地址未对齐（目标地址）、加载/存储地址未对齐（有效地址）、I-port 指令访问错误（取指地址）、D-port 加载/存储访问错误（数据地址）、`ECALL`、`EBREAK`。原因编码可以在特权 CSR 阶段映射为标准 `mcause`，但内部枚举值必须稳定。

异常记录随流水项携带 `pc`、原始指令（如可得）、原因和 `tval`。异常项及其之后的年轻项不得写回寄存器或产生新的内存副作用。

### 7.2 提交规则

* 仅 WB 级有效项可以产生通用寄存器写回和提交事件。
* 存储只有在事务成功后才能被视为外部可见并宣称提交；若响应报错，接口保证没有写副作用，该项转为异常。
* 更老项完成前，年轻项的异常不能抢占；同一项多个异常按架构规定固定优先级。
* 在未实现特权模式前，异常出口应至少提供 `trap_valid/trap_pc/trap_cause/trap_tval` 观测并停止或跳转到平台指定的仿真陷阱地址。不得伪造已实现的 `mepc/mtvec` 行为。

### 7.3 未来特权边界

特权扩展加入后，陷阱入口、`mstatus/mepc/mcause/mtval/mtvec`、`MRET/SRET`、中断采样和 `WFI` 由 CSR/特权单元拥有；流水线只负责在精确边界提交 trap 请求并接受 flush/redirect。CSR 写后读、异常优先级和中断屏蔽必须通过独立测试。

## 8. 未来缓存、总线、主存与设备接口

### 8.1 核心到地址转换层

I-port 和 D-port 请求分别保留虚拟地址、访问类型、大小、特权属性和顺序屏障信息。MMU 未实现时，两个适配器都将地址视为物理地址并直通。MMU 启用后，I-MMU 只处理取指转换，D-MMU 处理加载/存储/原子转换；转换失败必须返回页故障元数据，不得把失败地址送入缓存或总线。

### 8.2 TLB 与 Sv39

Sv39 阶段至少需要 ITLB、DTLB、可共享的页表遍历器（PTW）、`satp`、`SFENCE.VMA` 失效通道以及权限检查（`R/W/X/U`、`A/D`）。TLB miss 可以独立阻塞对应 I/D 通道，但不能丢失原始访问类型和精确异常 PC。PTW 使用物理地址访问，作为独立互连主设备或经受控的 D 侧物理通路发起请求，并遵守 PMP/缓存层顺序。

### 8.3 缓存与互连

缓存层位于 MMU（虚拟地址到物理地址）之后，初期建议采用物理索引/物理标记的阻塞式 I-cache 和 D-cache。I-cache 与 D-cache 的 tag/data、miss 状态和核心侧通道独立；它们只在下层互连和内存控制器处汇聚。缓存侧至少区分：

* I-cache 核心请求：32 位取指、失效、响应错误；
* D-cache 核心请求：读、写、原子、屏障、旁路、响应错误；
* 下游行请求：读行、写回行、写通、来源通道和响应错误；
* 一致性和原子保留（A 扩展）所需的锁定/监视元数据。

互连适配器可以选择 AXI4-Lite/AXI4、TileLink 或项目自定义协议，但要提供事务 ID、响应错误、背压和 I/D 请求间的有界公平性。统一 DRAM 控制器负责把来自 I-cache、D-cache、PTW 和 DMA 的主存请求调度到 DRAM；“统一”只描述这一层的 DRAM 控制器，不改变核心的改进哈佛接口。核心不应直接依赖某一种外部总线。

### 8.4 RAM、MMIO 与块设备边界

RAM/DRAM 是可直接寻址的易失性主存，ROM 是启动存储器；二者由内存控制器或只读适配器响应。UART、CLINT、PLIC、块设备控制器等是 MMIO 设备，只能通过标记为 device/uncached 的 D-port 访问，不能进入 I-cache 或作为普通可缓存 RAM。

硬盘、SSD 或仿真磁盘镜像是块设备介质，不与 RAM 共用加载/存储语义。CPU 通过 MMIO 配置 virtio-blk 或其他块控制器，控制器再通过 DMA 主设备在 DRAM 与设备介质之间搬运数据。DMA 必须经过互连、地址范围检查和未来的一致性/缓存维护规则。文档、地址图和测试中必须分别使用“主存”“MMIO 寄存器”“块设备介质”，不能统称为统一内存。

### 8.5 原子与多核预留

当前最小 reservation 监视器和阻塞式 AMO 只覆盖单核 D-port 内部顺序。进入 cache/互连阶段后，reservation set、SC 和 atomic read-modify-write 必须携带明确的原子属性穿过 D-cache 与互连；失效条件至少包括冲突的其他 hart 写入、DMA 写入以及实现规定的异常/上下文切换事件。互连尚未提供原子锁定、cache 尚未提供一致性、DMA 尚未监听 reservation，因此当前不能宣称系统级原子性或多核一致性。

## 9. 验证契约

每个阶段至少保留以下可重复证据：

1. 编译/Verilator lint 无新增警告（或对已知警告有登记）；
2. 定向指令测试覆盖算术、分支、访存、异常和流水停顿；
3. I-port 和 D-port 分别随机化 `ready/valid` 延迟，并覆盖两端口同周期请求、零延迟、长延迟和独立错误响应；
4. 提交轨迹可与参考模型（初期可为解释器，后续可接 Spike）逐条比较；
5. 关键断言：`x0==0`、无效项无副作用、每个已接受请求最终恰有一个响应、错误路径不提交、异常精确到最老项。

Icarus 只用于短小冒烟测试，不作为 SystemVerilog 完整语义或最终通过依据。波形、覆盖率数据库和临时编译产物写到仓库外的工作目录。

## 10. 参数与兼容性策略

架构常量（`XLEN`、`RESET_PC`、是否启用扩展）集中在 package/配置层；流水寄存器和接口字段不得散落魔数。扩展启用必须同时更新解码、异常、提交轨迹和测试矩阵。任何改变 I/D 端口握手、I/D cache 边界、DRAM 控制器汇聚、设备/DMA 接入或提交顺序的修改都视为架构级变更，需要更新本文、路线图门槛和变更记录。
