# RV64 处理器路线图

本路线图把“能运行”拆成可证明的阶段。阶段完成的含义是通过验收门并保留复现材料，不是代码文件已经存在。阶段可以并行准备，但依赖关系不可跳过。

## 总览

| 阶段 | 目标 | 主要依赖 | 软件/验证出口 |
| --- | --- | --- | --- |
| 0 | 工程基线 | 无 | 原生 Windows 构建、lint、最小仿真 |
| 1 | `RV64I` 五级流水 | 0 | 裸机汇编和 RV64I 指令测试 |
| 2 | `M/A` | 1 | RV64IMA 核心功能基线；系统级原子验收进行中 |
| 3 | `F/D/C` 数据通路扩展 | 2 | C 整数基线已形成；F/D 与阶段验收进行中 |
| 4 | `Zicsr/Zifencei` 与特权架构 | 3 | 完整 RV64GC 配置、M/S/U、异常、中断 |
| 5 | `Sv39` MMU | 4 | 页表、TLB、分页异常、用户态隔离 |
| 6 | 独立 I/D cache、互连、主存控制器 | 5 | I/D 通道汇聚到统一 DRAM 控制器 |
| 7 | MMIO 平台与块设备 | 6 | UART、CLINT/PLIC、块控制器、DMA |
| 8 | OpenSBI、Linux、Ubuntu | 7 | 内核启动、init、Ubuntu 用户空间 |

## 阶段 0：工程基线

### 交付物

* 目录、模块命名和 SystemVerilog 编码约定固定。
* Verilator 在 Windows 原生环境完成 lint 和一个最小可执行仿真；Icarus 能运行极短冒烟用例。
* 仓外工作目录约定为 `D:\Develop\AI\codex-work\riscv`，波形、覆盖率和中间文件不进入 Git。
* 基本时钟/复位、独立 32 位 instruction 取指端口、独立 64 位 data 访存端口和测试平台接口有文档。

### 验收门

1. 在干净 PowerShell 会话中可重建，不依赖 WSL、Linux shell 或用户私有环境变量。
2. I-port/D-port 分别施加 `valid/ready` 随机背压且允许同周期事务，不会导致死锁；复位期间没有请求或提交。
3. 至少有一条测试从复位取指到结束状态，波形可定位 PC 和流水级。
4. 失败命令、工具版本和生成物位置记录在操作日志中。

## 阶段 1：RV64I 五级流水

### 交付物

* 完整 RV64I 基础整数解码、立即数和 `W` 类操作。
* IF/ID/EX/MEM/WB 顺序流水，EX 级分支决定，无预测。
* 独立改进哈佛接口：32 位只读取指端口与 64 位加载/存储数据端口；数据端支持 8/16/32/64 位对齐访问、符号/零扩展。
* EX/MEM、MEM/WB 前递，load-use 停顿，分支冲刷，精确同步异常出口。

### 验收门

* 通过项目维护的 RV64I 定向测试和可运行的架构测试子集；每条失败指令能定位提交前后的轨迹。
* 分别随机化 I-port/D-port 响应延迟、请求拒绝和错误，确认每个接受请求恰好一个响应，并覆盖两个端口同时活动。
* 覆盖 x0、分支目标、`JALR` 清零最低位、边界地址、所有加载扩展和存储字节使能。
* 与参考解释器或 Spike 对比至少一个无操作系统的程序，逐条提交一致。

## 阶段 2：M/A 扩展

当前进度：已形成 `RV64IMA` 核心功能基线。`M` 的全部 64 位和 W 类指令已经接入核心并通过定向回归；`A` 已在单核阻塞式 D-port 下实现完整 LR/SC 和基础 AMO 的 W/D 形式。由于原子总线属性、随机并发、访问错误和编译器自旋锁等完整验收尚未完成，阶段 2 仍未关闭。

### 交付物

* `M`：64 位及 `W` 形式乘法、除法和取余，明确除零与最小负数溢出结果。
* `A`：已实现 `LR.W/D`、`SC.W/D` 和 `AMOSWAP/ADD/XOR/AND/OR/MIN/MAX/MINU/MAXU.W/D`；W 形式的旧值写回按规范符号扩展。
* reservation：普通 store 清除本地 reservation；SC 失败返回非零且不写内存，成功返回零；尚无其他 hart 或 DMA 写监听。
* 顺序：`aq/rl` 在当前顺序单发射、单 outstanding 模型下由强顺序自然满足；增加并发访存结构后必须重新验证。
* 乘除单元可多周期阻塞 EX；流水控制不会重复执行或丢失指令。

### 验收门

* 保持 M 参考模型对商/余边界的覆盖，并完成 A 指令 W/D 结果、旧值符号扩展、SC 成功/失败和普通 store 清 reservation 的定向回归。
* 增加随机并发测试，验证 AMO 读改写在外部主设备参与时仍满足协议定义的不可分割性。
* 接入 D-port 访问错误，验证 LR/SC/AMO 出错时不会错误写回、建立 reservation 或产生部分写入。
* 对外总线接口增加并验证原子锁定/独占属性；在该项完成前，当前 AMO 只对本核心阻塞式 D-port 有效。
* 运行编译器生成的原子自旋锁和简单线程程序，保存可重复的提交轨迹与结果。
* 多核 cache 一致性与 DMA reservation 监听属于后续互连阶段；在完成前不宣称多核或 DMA 一致的系统级原子支持。

## 阶段 3：F/D/C 数据通路扩展

当前进度：已形成 RV64C 整数功能基线，覆盖 16 位解压、`IALIGN=16`、2/4 字节 PC 步进，以及 32 位指令从高半字开始时的跨取指字拼接。F/D 浮点数据通路、压缩浮点形式、随机取指背压和编译器程序验收仍未完成，因此阶段 3 尚未关闭。

### 交付物

* `F/D`：浮点寄存器堆、舍入模式、异常标志、`fcsr`，以及单/双精度算术、转换、比较和加载/存储。
* `C`：已实现 RV64 整数压缩指令、HINT/保留编码分类、`IALIGN=16`；在 32 位 instruction 端口上处理半字选择及跨取指字边界拼接。压缩浮点形式等待 F/D。
* 浮点流水停顿、前递和 NaN/舍入语义与参考实现一致。

### 验收门

* 保持压缩整数定向回归和全部 65,536 个半字的解压分类对照；F/D 接入后补充压缩浮点与浮点算术测试，明确 NaN、无穷、非正规数和舍入边界策略。
* 使用已启用 I/M/A/F/D/C 指令子集（不依赖 CSR 或 `FENCE.I`）的小型 C 程序可编译、链接并在裸机平台运行；完整 `-march=rv64gc` 入口留到阶段 4。
* 取指缓冲在任意半字地址、内存背压和分支冲刷下不重复/丢失指令。
* 未启用的扩展编码仍产生非法指令异常；此阶段尚不因字母扩展齐全而宣称完整 `RV64GC`，还需阶段 4 的 `Zicsr/Zifencei`。

## 阶段 4：Zicsr/Zifencei 与特权架构

### 交付物

* `Zicsr` CSR 指令和 `Zifencei` 取指一致性语义；至此才形成标准 `G` 所要求的基础扩展组合。
* M/S/U 模式、CSR 读写、`mstatus/misa/mtvec/mepc/mcause/mtval` 等最小集合。
* `ECALL/EBREAK/MRET/SRET`，同步异常精确入口和返回。
* 定时器、外部中断输入，初步定义 `WFI` 行为和中断屏蔽。
* PMP 或等价物的最小权限检查，且与取指/加载/存储类型区分。

### 验收门

* 特权测试验证模式切换、非法 CSR、异常嵌套/返回和 `mstatus` 位更新。
* 中断在指令边界采样，不能让年轻流水项提交；屏蔽位和优先级可由测试观察。
* 最小 M-mode 固件能设置陷阱向量、响应定时器中断并返回。
* 与规范版本、实现的未实现 CSR 行为和 WARL/WPRI 位策略有明确记录，并可在通过后声明 `RV64GC` 配置。

## 阶段 5：Sv39 MMU

### 交付物

* `satp`、三级页表遍历器、ITLB/DTLB（可先阻塞式）、`SFENCE.VMA`。
* 页权限检查（R/W/X/U）、访问位/脏位策略、PMP 与页表访问的顺序。
* 指令、加载、存储页故障及访问异常，保留原始虚拟地址为 `tval`。

### 验收门

* 4 KiB 页、超级页、TLB 命中/失效、ASID/全局页和 `SFENCE.VMA` 用例通过。
* 用户态无法执行/读写不允许的页；故障 PC、原因和 `tval` 与参考模型一致。
* 页表遍历在总线背压、缓存未命中和错误响应下不会死锁或污染 TLB。
* 至少运行一个带用户态进程切换的分页裸机测试，再进入软件启动阶段。

## 阶段 6：独立 I/D cache、互连与主存控制器

### 交付物

* 独立阻塞式物理 I-cache 和 D-cache，保留分离的核心侧通道、miss 状态、写策略、失效和 `FENCE.I` 语义。
* 下层互连/总线适配器按来源区分 I-cache、D-cache、PTW 和未来 DMA 请求，提供背压、错误和有界公平仲裁。
* 统一主存控制器将多主设备请求调度到 DRAM；该汇聚不改变 CPU 核心的改进哈佛接口。
* ROM/DRAM 地址范围、cacheable/uncacheable 属性和内存屏障路径固定。

### 验收门

* I-cache/D-cache 分别覆盖命中、未命中、回写、替换、失效和错误响应；I/D miss 同时发生时不会串错响应。
* 主存控制器在 I-cache、D-cache、PTW 并发下保持有界公平，不因单一通道持续请求而饿死其他通道。
* DRAM 地址空间和 ROM 载入在 Verilator 长时间仿真中稳定，所有主存事务可追踪到来源。
* 总线协议违规可被监视器捕获；MMIO 和块设备尚不作为本阶段主存验收的替代品。

## 阶段 7：MMIO 平台与块设备

### 交付物

* UART、CLINT、PLIC、测试终止设备等 MMIO 控制器和明确的平台地址图。
* virtio-blk 或项目选择的块设备控制器；CPU 仅通过 D-port 的 uncached MMIO 访问其寄存器。
* 块设备 DMA 主设备，经互连在 DRAM 缓冲区与独立磁盘镜像/设备介质之间搬运数据。
* 设备树（DTB）生成或加载流程，准确描述主存范围、MMIO 中断和块设备，不能把磁盘容量写成 RAM。

### 验收门

* MMIO 请求绕过 D-cache，I-port 对设备地址取指产生访问错误；设备寄存器不会被当作普通主存。
* UART 输出和 CLINT/PLIC 中断端到端到达正确特权入口。
* 块设备至少完成可重复的扇区读写、错误注入和中断测试；磁盘镜像变化不会修改 DRAM 初始化镜像。
* DMA 只能访问配置允许的 DRAM 范围，并验证与 D-cache 的维护/一致性策略；在策略完成前使用显式 flush/invalidate 或 uncached 缓冲区。
* 地址图、DTB、磁盘镜像哈希和设备模型版本均进入可复现记录。

## 阶段 8：OpenSBI、Linux 与 Ubuntu

### 交付物

* OpenSBI 在 M-mode 启动，向 Linux 提供 SBI 定时器、IPI（单核可返回受限状态）和 console 等服务。
* Linux 内核配置与设备树匹配；能挂载 initramfs，或通过独立 virtio 块设备挂载根文件系统。
* Ubuntu 用户空间镜像、启动参数和复现脚本。第一验收目标为 Ubuntu Server/最小用户空间到登录 shell；桌面环境另列平台和图形设备工作包。

### 验收门

1. 复位后经过 ROM/OpenSBI 进入 Linux，不依赖人工修改寄存器或仿真器注入状态。
2. 串口可见内核早期日志、SBI 调用和用户空间 `init`，无未处理的非法指令/页故障循环。
3. 能执行基本命令、创建文件、启动一个用户进程并正常退出；文件系统错误可复现且可定位到设备事务。
4. 同一提交、同一镜像和同一 Verilator 版本在干净工作目录重复启动，结果和退出原因一致。
5. 保存启动日志、DTB、内核配置、镜像哈希和仿真参数；完成后再评估性能、SMP 和桌面支持。
